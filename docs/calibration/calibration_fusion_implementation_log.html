2026-05-25: Scenario Debugging And Model Corrections

Implemented: Added an evidence gate to prior assembly: a MultiLocus must have both finite gDNA candidates and positive fused regional upper mass before native EM may enable gDNA. This prevents zero-evidence loci from exploiting the native EM log floor.

Implemented: Corrected the deterministic-zero density branch so no-fitted-prior regions have zero mean, zero upper bound, zero predictive variance, and a point mass at D=0. Boundary-compatible observations are no longer interpreted as forced gDNA when the reference density is zero.

Implemented: Added a sparse intergenic fallback prior for small simulations with positive intergenic contained evidence but too few anchor regions for the robust Gamma fit. Sparse intron-only evidence remains deterministic zero because it can be nRNA.

Implemented: Fixed the large-count approximate fusion path so zero-variance density evidence remains degenerate instead of falling into a boundary approximation. This removed a false 1900-count gDNA prior in a single-exon no-splice debug case.

Diagnostics: Added scripts/debug/debug_fusion_scenario.py for file-based inspection of fused evidence, prior allocation, loci, and transcript counts in selected synthetic scenarios.

Tests: Added regressions covering deterministic-zero boundary handling, sparse intergenic fallback, sparse intron-only zero fallback, zero-upper gDNA disablement, and large-count deterministic-zero fusion.

Validation: conda activate rigel && pytest tests/scenarios tests/scenarios_aligned -v passed: 176 passed.

Deviation: The v2 plan described deterministic-zero fallback, but did not spell out the sparse intergenic fallback. This was added because small synthetic runs can contain real intergenic gDNA anchors while still falling below the robust fit region threshold.

Unexpected issues: The previous zero-density fallback was using boundary-compatible mass as local gDNA evidence; that fixed true-gDNA toy cases but created false gDNA in no-gDNA nRNA cases. The sparse intergenic fallback preserves true-gDNA recovery without reopening intronic nRNA leakage.

2026-05-25: Capture Weighting Repair

Implemented: Fixed hybrid-capture sparse weighting so split blocks from one junction-spanning probe are summed within that probe, while distinct probes still use the best single-probe score and do not stack.

Tests: conda activate rigel && pytest tests/test_sim_capture.py -v passed: 10 passed.

Deviation: This repair is outside the calibration fusion plan, but it was required to make the pre-existing capture tests green before final full-suite validation.

Unexpected issues: The old implementation preserved the non-stacking rule but lost probe identity after splitting a transcript or BED12 probe into genomic/pre-mRNA blocks, so it took the best split block instead of the best whole probe.
