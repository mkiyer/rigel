Fine Region Migration Implementation Log

Started: 2026-05-22. Scope: phased implementation from fine_region_migration_design_v3.md.

Current Status

Phase 0, Phase 1, and Phase 2 implementation complete. Phase 3 planning and interface audit are drafted in fractional_accumulator_phase3_plan.md; implementation has not started.

Planned Phase 3 Tasks

  • Replace the integer calibration accumulator with sparse per-worker fractional region counts.
  • Export the 12-channel fractional payload and joint FL marginals needed by downstream code.
  • Remove accumulator-side splicing-anchor tolerance while keeping resolver-side tolerance provenance.
  • Define current-compatible audit views that use unspliced-only contained mass.
  • Break and then redesign the downstream density, exposure, and prior interfaces around fractional evidence.

Planned Phase 2 Tasks

  • Add fine signatures, neighbor signatures, and boundary kinds to the native RegionIndex.
  • Expose native accessors and update the set_regions binding.
  • Wire the v4 region columns through pipeline._wire_calibration_regions(...).
  • Add focused native metadata tests.
  • Rebuild native extensions and run targeted verification.

Planned Phase 1 Tasks

  • Replace the coarse region emitter with the fine-signature region builder.
  • Add the v4 regions.feather schema and hard-fail pre-v4 region tables.
  • Bump INDEX_FORMAT_VERSION to 4 and keep derived coarse bridge columns.
  • Extend region arrays, persistence validation, and focused tests.
  • Run focused verification; refresh goldens only if the test batch requires it.

Planned Phase 0 Tasks

  • Create Python signature/channel helpers.
  • Create native C++ signature/channel mirror.
  • Add Python signature tests and Python-to-native layout tests.
  • Fix calibration region wiring to use index-level reference mapping and warn on dropped refs.
  • Remove legacy calibration-region wiring fallback.
  • Run targeted verification.

Deviations

  • Using existing tests where they already cover the touched Phase 0 surface; the named future test files in the design are not all present yet.
  • Applied formatter output after initial successful tests; repeated the relevant test batches afterward.
  • For Phase 1, retained the existing tests/test_region_partition.py filename rather than creating a separate tests/test_regions.py; the coverage now targets the fine builder.
  • Did not create a committed tests/_v3_builder_snapshot/; instead, validation checks the v4 derived columns directly against signatures and neighboring rows.
  • RegionArrays.from_region_df(...) includes a temporary in-memory coarse-to-signature bridge for older hand-built unit-test frames. Runtime index loading remains strict: persisted pre-v4 region tables are rejected.
  • For Phase 2, exposed a small native RegionIndex class through rigel.native to test metadata accessors directly. Production calibration wiring still uses BamScanner.set_regions(...).
  • For Phase 3 planning, added a separate detailed plan document rather than editing implementation code. This keeps the fractional accumulator cutover reviewable before the breaking native/Python payload changes begin.

Issues

No blocking implementation issues. Phase 1 intentionally changed golden outputs in scenarios where fine signatures alter derived coarse bridge exposure, especially antisense/gDNA/strand-sensitive cases. The changes were refreshed through the test harness and verified by rerunning the golden tests. Phase 2 did not change golden outputs; it only carries v4 metadata through native region setup.

Phase 3 planning issue: downstream calibration code is deeply coupled to the old integer payload. This is expected and should break visibly during the cutover rather than being hidden behind compatibility arrays.
