What was built

  • Constants: DNA_STRAND_UNIFORM_PRIOR = 2.0, MAX_EXACT_POSTERIOR_N = 200, and uint8 flag bits (INELIGIBLE, NEAR_UNSTRANDED, KAPPA_FALLBACK, APPROX_NORMAL, EXON_SELF_TRAIN).
  • Dataclasses:
    • StrandRegionCounts — per-region folded (k_sense, k_antisense, n_total, eligible) plus p_r1_sense.
    • RegionGdnaEstimate — per-region (mean_count, upper_count, rna_lower_count, precision, flags) with global kappa_d and the seed/exon counts driving it.
    • KappaDEstimate — wraps the refit StrandBalanceEstimate plus seed/exon region counts. Its fallback_used property reports only hard/uniform-prior fallback, not the soft κ=max clip. (see Deviation 1 and 3)
  • Functions:
    • build_strand_region_counts(region_arrays, payload_arrays, *, p_r1_sense)
    • deconvolve_regions_by_strand(counts, *, kappa_d, rna_lower_confidence, …)
    • screen_no_rna_exons(counts, region_arrays, payload_arrays, kappa_d_seed, *, rna_lower_confidence)
    • estimate_kappa_d(region_arrays, payload_arrays, counts, strand_summary, *, rna_lower_confidence)
  • Internal helpers: _exact_posterior_R, _summarize_exact, _summarize_normal, _log_binom_pmf, _log_beta_binom_pmf, _refit_with_fallback, _is_hard_fallback.

Generative model implemented

Per eligible region: D = n − R, k_sense = DNA_sense + RNA_sense with DNA_sense | D ~ BetaBinomial(D, α=κd/2, β=κd/2) and RNA_sense | R ~ Binomial(R, p_r1_sense). For n_total ≤ MAX_EXACT_POSTERIOR_N we evaluate the discrete posterior P(R = r | k_sense, n) over all r ∈ {0,…,n} by convolving the binomial × beta-binomial PMFs in log space (with a uniform prior on R). Larger regions fall back to a normal approximation linearised around the MLE R̂ = (k_sense − n/2)/(p_r1_sense − 0.5), with variance evaluated at R̂ and the (1−c)-quantile derived from scipy.stats.norm.ppf.

Identifiability guard: when |p_r1_sense − 0.5| < STRAND_CONTRAST_NUMERICAL_FLOOR the region is marked FLAG_NEAR_UNSTRANDED and reported as fully gDNA (no RNA lower bound).

Deviations from the plan

Deviation 1 — estimate_kappa_d returns a richer wrapper

The plan's signature is estimate_kappa_d(…) → StrandBalanceEstimate. The plan also adds two acceptance tests that require knowing the seed-vs-exon split (e.g. test_kappa_refit_uses_accepted_exons). A bare StrandBalanceEstimate only carries the combined n_regions count, so we cannot separate the two populations downstream.

Implemented as KappaDEstimate, a tiny frozen dataclass:

@dataclass(frozen=True, slots=True)
class KappaDEstimate:
    balance: StrandBalanceEstimate     # refit (or seed if no self-training)
    n_seed_regions: int
    n_exon_self_training: int
  @property kappa                       # delegate to balance
  @property fallback_used               # hard fallback only

This keeps the math closed and gives the Phase 4 orchestrator the diagnostics fields named in RegionGdnaEstimate (kappa_d_n_seed_regions, kappa_d_n_exon_self_training) without a second pass.

Deviation 2 — Exon screen reformulated as a tail p-value

The plan phrases the screen as P(R > 0 | data, κdseed) ≤ 1 − c. Implemented literally with a uniform prior on R ∈ {0,…,n} the criterion is essentially unreachable for finite n: even pure-gDNA data with the tightest plausible κ leaves the singleton P(R = 0) diluted across an entire integer grid. With n = 200, p_r1_sense = 0.95, κ = 106 and balanced counts k_sense = 100, the singleton posterior at R = 0 is only ≈10 %, while the truncated mass within R ∈ [0, 20] is > 70 %.

We replaced the criterion with the natural frequentist reading:

Accept the region iff the observed k_sense is not rejected under H₀: k_sense ~ BetaBinomial(n, κ/2, κ/2) at level 1 − c.

The implementation computes a two-sided tail p-value (sum of all k with PMF ≤ PMF(k_obs)) and accepts when p ≥ 1 − c. This matches the spec's intent ("is the strand pattern consistent with pure gDNA?") and is the standard reading of "no-RNA exon".

The reformulation is documented in the screen_no_rna_exons docstring and re-used by estimate_kappa_d. The deconvolution function still uses the discrete posterior — that path is well-behaved because we summarise it as a mean / quantile pair rather than asking for a singleton mass.

Deviation 3 — Hard vs soft fallback for κd

The plan calls for DNA_STRAND_UNIFORM_PRIOR = 2.0 as the κd fallback "when MoM fails". estimate_strand_balance raises fallback_used = True in three distinct situations:

  1. n_regions < MIN_REGIONS_FOR_STRAND_MOM — no data.
  2. "no positive strand exposure" — no data.
  3. "residual variance <= binomial expectation" — data are tighter than Binomial(0.5), kappa is clipped to STRAND_KAPPA_MAX = 106.

Case 3 is information, not uncertainty — the right κd really is "very large". Substituting κd = 2 here would over-disperse the gDNA strand model and make the screen reject too many balanced exons. We therefore distinguish "hard" fallbacks (1, 2) from "soft" (3) via a small private set _HARD_FALLBACK_REASONS, and only substitute the uniform prior on hard fallback. Soft fallbacks pass through unchanged and self-training proceeds against the tight κ.

Review follow-up: _is_hard_fallback now normalizes annotated fallback reasons before comparison, so a reason like "n_regions < MIN_REGIONS_FOR_STRAND_MOM; using DNA_STRAND_UNIFORM_PRIOR" is still recognized as hard fallback. KappaDEstimate.fallback_used now reports this hard-fallback state only; the underlying balance.fallback_used may still be true for the soft STRAND_KAPPA_MAX clip. This prevents Phase 4 from marking every region with FLAG_KAPPA_FALLBACK when the data are merely tighter than Binomial(0.5).

Deviation 4 — Test fixtures use realistic κ values

Two of the prescribed unit tests (test_exon_screen_accepts_balanced_no_spliced_exon, test_kappa_refit_uses_accepted_exons) were originally written with κd = 10 — the order of magnitude expected for biological strand mismatch, not for the gDNA strand-balance prior, which is typically > 103. The screen p-value approach is well-behaved at any κ; the dataset just has to actually look like the H₀ distribution. We tightened the seed counts (residuals near binomial expectation, so MoM clips to STRAND_KAPPA_MAX) and the boundary-test contrast (p = 0.99, κ = 104). All other tests use the parameter values from the plan as-is.

Unexpected findings

Finding A — Normal approximation is biased for moderate κ

Evaluating the conditional variance at R̂ (rather than averaging over the posterior) underestimates the skew that the heteroscedastic BetaBinomial induces when κ is small. For n = 200, p = 0.9, κ = 10, the exact posterior mean of R can sit ≈13 counts below the MLE while the normal approximation reports the MLE exactly. The discrepancy disappears for κ > 103, which is the regime we actually see in gDNA strand balance. Recorded in the boundary test's docstring; not worth iterating further unless real data show small-κ regions in the deconvolution path.

Finding B — Exact discrete path cost

The exact posterior is O(n²) per region: an outer loop over r ∈ {0,…,n} and an inner convolution over j. At MAX_EXACT_POSTERIOR_N = 200 the inner work is bounded by ≈40 000 PMF evaluations per region (~milliseconds). For real loci this is comfortable; we will revisit the cap during Phase 4/5 profiling once we know how many fine regions per locus need deconvolution.

Finding C — Identifiability bookkeeping

The plan tags a region as "near-unstranded" using the existing STRAND_CONTRAST_NUMERICAL_FLOOR = 1e-3. We extend the same flag to ineligible regions (TS_AMBIG / TS_NONE / n_total = 0) so a downstream consumer only has to consult flags & FLAG_INELIGIBLE or flags & FLAG_NEAR_UNSTRANDED to know whether the per-region estimates are trustworthy. The plan's FLAG_INELIGIBLE bit therefore takes a broader meaning than "ts_class is not ±1": it also covers empty regions.

Finding D — Boundary numerics needed explicit tests

A review pass found two edge cases that were not covered by the original Phase 3 test list. First, exact binomial likelihoods at p_r1_sense = 0 or 1 need explicit degenerate PMFs; clipping by an epsilon smaller than machine precision can produce 0 * -inf and nan. Second, the exact posterior rounds fractional accumulator counts onto an integer grid, but public outputs must remain on the original fractional scale. The implementation now handles degenerate binomial probabilities exactly and clamps mean_count, upper_count, and rna_lower_count into [0, n_total].
