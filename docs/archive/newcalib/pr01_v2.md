# PR 01 v2 - Two-State Expression Filter Implementation Plan

## Purpose

PR 01 removes the four-state capture classifier from production calibration and replaces it with a
two-state expression filter:

```text
STATE_UNEXPRESSED = 0
STATE_EXPRESSED = 1
N_STATES = 2
STATE_NAMES = ("unexpressed", "expressed")
```

The output of this PR is not the final exposure-aware calibration system. It is the safe teardown
step that keeps the pipeline running while capture/exposure logic is rebuilt in later PRs.

## Non-Goals

- Do not implement `omega_r` exposure shrinkage.
- Do not add native support counts.
- Do not fix the downstream exposure denominator sign yet.
- Do not preserve capture-state compatibility fields unless they are explicitly listed below as
  temporary shape-preserving handoffs.

## Critical Safety Rails

### 1. Interim `mu_gdna` Handoff

Downstream prior assembly currently requires `RegionCalibration.mu_gdna`, `upper_gdna`, and
`prior_mass`. PR 01 must keep those shapes valid even though capture-derived `mu_gdna` is deleted.

Use a deliberately simple interim projection:

```text
mu_gdna_interim_r = rho_off * contained_leff_r
upper_gdna_interim_r = NB/Gamma upper bound from background only
```

Implementation detail:

```text
off_target_mu = background.rho_off_mean * observation.contained_leff
upper_off_target = predict_contained_gdna_from_excess(
    background,
    observation.contained_leff,
    zeros,
    zeros,
)
mu_gdna = off_target_mu
upper_gdna = max(upper_off_target, mu_gdna)
```

This does not claim to be the final regional gDNA mass estimator. It preserves the downstream
contract until PR 03 introduces `RegionGdnaMass`.

When strand deconvolution is available, `build_prior_mass_deconvolution()` should continue to use
the compartment strand means and reliabilities rather than `mu_gdna_interim`. When strand
deconvolution is unavailable, the density fallback uses the interim background projection.

### 2. Bootstrap Background Remains Heuristic

The first call to `fit_background_model()` happens in `_orchestrator.py` before any E-step has
created `p_unexpressed`. Do not try to pass expression posteriors into this bootstrap call.

The execution path is:

1. `_orchestrator.py` bootstrap: `fit_background_model()` keeps using hard heuristic masks:
   `candidate & ~top_t_exclusion & ~strand_rna_evidence`.
2. `calibration_iteration.py` iterative M-step: refit background with soft weights:

```text
unexpressed_weight_r = p_unexpressed_r * seed_mask_r
n_fragments = sum_r unexpressed_weight_r * gdna_count_r
eff_length = sum_r unexpressed_weight_r * contained_leff_r
rho_next = (alpha_floor + n_fragments) / (beta_floor + eff_length)
```

This avoids the bootstrapping paradox and gives later passes expression-aware background updates.

### 3. Prior Eligibility Is Expression-Only

The current adaptive prior uses normalized entropy over four states. After PR 01 there are only two
states, so this no longer measures capture uncertainty. Do not pretend it does.

Implementation deviation from the original v2 draft: the final review correctly points out that an
expression margin is still symmetric. PR 01 should use a directional soft gate driven by
`p_unexpressed`, not `abs(p_unexpressed - p_expressed)`.

```text
region_weight_r = p_unexpressed_r
```

This makes the semantics plain:

- `1.0`: confidently unexpressed and eligible for prior placement,
- `0.0`: confidently expressed and rejected for prior placement,
- intermediate values are smooth soft weights that avoid threshold chatter.

Rename diagnostics from entropy language where practical. Suggested interim policy name:

```text
p_unexpressed_soft_gate_interim_no_exposure_gating
```

Keep the existing ESS cap. Add comments or summary text stating that capture/exposure-driven
variance is not gated in PR 01 and is deferred to PR 04.

`CalibrationStepResult`:

`calibration_e_step()`:

1. Build or validate `local_posterior` as today.
2. Run `run_boundary_sweep()` as today for diagnostics/future handoff.
3. Build the two-state tensor from prior, expression, and strand-expression terms only.
4. Set interim `mu_gdna` and `upper_gdna` from flat background projection.

- Refit background from `p_unexpressed * background.seed_mask`.

## Done Means

- No production code imports capture latent constants.
- `RegionCalibration.p_states` is two-state.
- Bootstrap background remains heuristic; iterative M-step background uses soft `p_unexpressed`.
- `mu_gdna` and `upper_gdna` remain downstream-safe via the interim background projection.
- Adaptive prior region gating is explicitly `p_unexpressed` based, not four-state entropy.
- Capture/exposure variance gating is documented as deferred to PR 04.

  proposed expression-margin confidence with the final-review recommendation, a directional soft
  `p_unexpressed` gate. Reason: expression margin is symmetric and would still trust confidently
  expressed regions; `p_unexpressed` smoothly accepts unexpressed regions and rejects expressed
  regions.
- 2026-05-28: Removed capture latent constants and capture/density log Bayes factors from the
  production latent tensor. `STATE_UNEXPRESSED`, `STATE_EXPRESSED`, and `N_STATES = 2` are now the
  production state contract.
- 2026-05-28: Detached `calibration_iteration.py` from capture posteriors. `mu_gdna` now uses the
  interim flat background projection, `A_r` is all ones, and `gamma_r`/
  `capture_enrichment_target` are removed from production calibration outputs.
- 2026-05-28: Updated targeted fixtures for two-state calibration and directional prior gating.
  First targeted run produced 52 passes and 2 expected assertion failures from old symmetric-prior
  expectations; patched those assertions to reflect that uniform regions contribute half-weighted
  mass and confidently expressed regions contribute no adaptive prior mass.
- 2026-05-28: Second targeted run exposed an implementation issue: the old low-confidence global
  pool fallback could leak priors into confidently expressed loci when `p_unexpressed = 0`. PR 01
  now treats `p_unexpressed` as an eligibility gate and uses weighted local prior mass only;
  global-pool shrink blending is disabled until a future confidence model is introduced.
- 2026-05-28: Validation after the local-mass gate change passed: targeted PR 01 suite reported
  54 passed; pipeline smoke reported 13 passed; broader calibration sweep reported 72 passed;
