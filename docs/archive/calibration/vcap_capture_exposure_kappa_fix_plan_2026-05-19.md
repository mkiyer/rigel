# VCaP Capture Exposure Kappa Fix Plan - 2026-05-19

## Context

The VCaP RNA/gDNA mix is hybrid-capture data: both the RNA library and the gDNA
library were exposed to the same exon-targeted probe panel. A good regional
exposure model should therefore learn high exposure on targeted exons and low
exposure in introns/intergenic sequence. The failure mode is not that
EXON-INTRON density is high. That is expected. The failure mode is that the
current shrinkage makes many exon rows with no boundary count collapse to near
zero exposure, which then shrinks RNA EM effective lengths and makes RNA
components too attractive.

Fresh v4.3 VCaP confusion result:

- True RNA source: 96.37% called RNA, 2.74% called gDNA.
- True gDNA source: 77.94% called gDNA, 20.44% called RNA.
- Most gDNA-to-RNA errors are ambiguous unspliced calls, split across nRNA and
  mRNA.

## Findings

### 1. Why kappa is 1

`estimate_kappa` returns a negative-binomial/Gamma-Poisson shape-like parameter
from method of moments. In the VCaP payload, every channel hits the configured
minimum value of 1.0, but it is not falling back:

| class | raw alpha | clipped alpha | rho | alpha/rho |
| --- | ---: | ---: | ---: | ---: |
| ALL | 0.940 | 1.0 | 1.887e-3 | 530 bp |
| INTERGENIC | 0.332 | 1.0 | 7.928e-6 | 126,134 bp |
| INTRON | 0.168 | 1.0 | 1.954e-4 | 5,117 bp |
| EXON-INTRON | 0.141 | 1.0 | 2.989e-2 | 33 bp |

The reason is extreme overdispersion/zero inflation in capture data. The raw
method-of-moments alpha is below 1 in all channels, so `KAPPA_MIN=1` clips it.

The bigger issue is dimensional. The posterior mean currently uses:

```text
rho_hat_r = (Y_r + kappa * rho_global) / (E_r + kappa)
```

In that formula, `kappa` must be prior opportunity length, in bp-equivalent
exposure units. But `estimate_kappa` returns an alpha/shape value, closer to
prior count strength. For a Gamma-Poisson prior, the opportunity-length
parameter is:

```text
beta = alpha / rho_global
```

For VCaP, the clipped alpha of 1 should imply about 530 bp of prior exposure,
not 1 bp.

The practical impact is large for zero-count regions:

| E probe | current kappa=1 | alpha/rho=530 | 5/rho=2,650 |
| ---: | ---: | ---: | ---: |
| 79 bp | 0.0125x global rho | 0.870x | 0.971x |
| 611 bp, median valid E | 0.00163x | 0.464x | 0.813x |
| 7,843 bp, q90 valid E | 0.000127x | 0.0633x | 0.253x |
| 71,240 bp, q99 valid E | 0.000014x | 0.00738x | 0.0359x |

This explains the floor-heavy field. With `kappa=1`, a median zero-count exon
row is treated as essentially unexposed even though exon capture is the expected
target signal.

### 2. EXON-INTRON boundary flux is necessary

The boundary-flux proxy is doing the right kind of work. Mature mRNA contaminates
contained exon counts, so contained exon density is not a safe gDNA exposure
observable. Boundary-crossing evidence is the mRNA-resistant way to infer exon
gDNA exposure from the existing BAM scan.

The VCaP boundary-side check supports the proxy rather than refuting it:

| exon boundary group | regions | rho |
| --- | ---: | ---: |
| all eligible | 318,828 | 0.029894 |
| internal, two sides | 273,250 | 0.029875 |
| terminal, one side | 45,578 | 0.030120 |
| left-only terminal | 22,789 | 0.030652 |
| right-only terminal | 22,789 | 0.029588 |

Internal and terminal exon rows have nearly identical density. This does not
look like a boundary-geometry artifact. It looks like real exon-targeted capture
exposure.

The concern is not boundary flux itself. The concern is that sparse boundary
observations are being treated with only 1 bp of shrinkage, so zero-boundary exon
rows become almost zero-exposure rows.

### 3. EXON Q99 or max is not a root-cause fix

The current reference is the global E-weighted Q95 of `rho_hat`:

```text
current rho_ref = 2.132e-4
EXON-INTRON Q95 = 0.1928  = 904x current rho_ref
EXON-INTRON Q99 = 0.3398  = 1,594x current rho_ref
EXON-INTRON max = 2.5617 = 12,015x current rho_ref
```

Because weights are capped as `A_r = min(rho_hat_r / rho_ref, 1)`, raising
`rho_ref` to EXON Q99 or max lowers almost every weight. It does not rescue
zero-count exons; it pushes more regions toward the floor.

For the top 50,000 expressed/output transcripts under the current `kappa=1`
field:

| field | mRNA median weight | nRNA median weight |
| --- | ---: | ---: |
| current global Q95 | 0.0191 | 0.0289 |
| global Q99 | 0.000103 | 0.000111 |
| EXON Q99 | 0.000100 | 0.000100 |

Using EXON max is worse: it normalizes to a handful of hottest regions and makes
nearly the whole field tiny. Max is not robust enough for capture data, copy
number, duplicates, probe outliers, or annotation quirks.

After converting alpha to prior opportunity length, the reference choice becomes
less pathological, but EXON Q99/max still should not be the first fix. Correct
the shrinkage units first, then benchmark reference choices.

## Recommended Fix

### P0: Repair the kappa units

Keep the current one-field model and keep EXON-INTRON boundary evidence. Change
the regional exposure builder so the method-of-moments value is treated as an
alpha/shape parameter, then converted to prior opportunity length before use in
the posterior mean:

```text
alpha = estimate_kappa(Y_valid, E_valid, rho_global).value
kappa_len = alpha / max(rho_global, eps)
rho_hat_r = (Y_r + kappa_len * rho_global) / (E_r + kappa_len)
```

Rename summary fields to avoid ambiguity:

- `kappa_alpha_global`: the NB/Gamma-Poisson shape estimate.
- `kappa_opportunity_bp`: the bp-equivalent shrinkage used in `E + kappa`.
- Remove the old ambiguous `kappa_global` summary field.

Add tests that pin the unit interpretation:

- A zero-count region with `E = alpha / rho_global` should shrink to exactly
  `0.5 * rho_global`.
- A zero-count region with `E << alpha / rho_global` should stay near global.
- A zero-count region with `E >> alpha / rho_global` should be allowed to fall
  below global.

This is not per-class normalization. It is a unit correction for the same global
latent field.

### P1: Keep the current reference until the kappa fix is benchmarked

Do not switch to EXON Q99 or max as part of the first patch. With the shrinkage
bug still present, hotter references make the floor problem worse. With the
shrinkage fixed, current global Q95 may already behave like a target-high
normalizer: exons cap near 1 while introns/intergenic remain lower.

Benchmark at least these reference choices after P0:

- global Q95, current behavior after corrected kappa;
- global Q99;
- EXON-INTRON Q95;
- EXON-INTRON Q99;
- never max as a production default.

Evaluate against both synthetic-24 and VCaP flowcell confusion. The VCaP primary
metric should be gDNA-source RNA leakage, with a secondary check that RNA-source
gDNA leakage does not rise sharply.

### P2: Add channel calibration only if needed

If P0 still leaves systematic bias, add a channel-calibrated likelihood for the
same latent field rather than per-class normalization. The three evidence
channels have different measurement mechanisms:

- INTERGENIC: contained-fragment evidence.
- INTRON: contained-fragment evidence with strand correction.
- EXON-INTRON: boundary-crossing evidence with strand correction.

A principled extension is a single latent exposure field `A_r` with
channel-specific observation variance or reliability, not separate normalized
fields. That preserves the model purpose: one exposure map in which exons can be
high and introns/intergenic can be low.

### P3: Longer-term capture support

For true hybrid-capture workflows, the cleanest model should eventually accept
or infer a capture target map:

- optional target BED/probe BED;
- target-aware region priors for exon rows;
- off-target decay or smoothing around targets;
- one optional refinement pass using posterior expected gDNA counts, capped so
  ambiguous RNA fragments cannot define the exposure field by themselves.

This is larger than the immediate regression fix. It should not block the kappa
unit repair.

## Bottom Line

I do not agree with dropping EXON-INTRON evidence or auto-uniforming VCaP. The
data are capture data, and EXON-INTRON density is supposed to be high. I do agree
that the current field is damaging EM denominators, but the root cause is the
shrinkage unit error plus sparse boundary observations, not the existence of an
exon-enriched exposure field.

The recommended first patch is: keep one field, keep boundary flux, convert NB
alpha to bp-equivalent prior opportunity, and benchmark reference choices only
after that correction.
