EXON Strand Deconvolution Audit Log v1

Date: 2026-05-20. Scope: calibration scanner payload, global densities, regional exposure, locus priors, and tests relevant to using strand-specific EXON-contained evidence with existing EXON-INTRON boundary flux.

Audit Entry 1: Existing Strand-Aware Calibration Surface

Files: src/rigel/calibration/density_global.py, src/rigel/calibration/_orient.py, src/rigel/pipeline.py, tests/test_density_global.py.

The calibration pipeline already has a reusable strand deconvolution implementation. StrandSummary stores p_r1_sense, signed_strand_contrast, and observation count. The calibration strand summary is trained from strand_models.exonic_spliced, which is the right RNA-pure source. The correction gate is strand_correction_usable(), using a 99 percent normal-approximation margin plus the numerical floor 1e-3.

The core correction is _gdna_count_moment(same, opp, signed_strand_contrast), which estimates gDNA counts as total - (same - opp) / contrast. This is already used for INTRON and EXON-INTRON channels. Existing tests pin unstranded fallback, perfect stranded pure-RNA zeroing, pure-gDNA symmetry, read-1 antisense mirror invariance, aggregate-before-final-clip behavior, ambiguous-row handling, and boundary orientation routing.

Implication: The feature should reuse this correction path. The new work is not a new strand model; it is a new EXON-contained observation channel and a fusion layer.

Audit Entry 2: Scanner Payload and Native Accumulator

Files: src/rigel/native/calibration/accumulator.h, src/rigel/native/calibration/accumulator.cpp, src/rigel/native/calibration/orient.h, src/rigel/native/bam_scanner.cpp, src/rigel/calibration/scan_payload.py, tests/test_calibration_accumulator.py.

The native accumulator currently emits per_region_counts, u_left, u_right, intron_counts_by_orient, u_left_by_orient, and u_right_by_orient. Orientation codes are consistent across C++ and Python: SAME=0, OPP=1, UNINF=2.

Boundary flux is computed for unspliced fragments touching EXON regions. It uses the observed fragment span [frag_start, frag_end) and a tolerance-derived clearance q = max(K, 1). Counters are recorded independently of boundary eligibility flags; eligibility is applied later in density code. This is a good design and should be preserved.

The missing payload is an EXON-contained orientation table. per_region_counts[:, MASK_EXON] is not usable because it includes mature mRNA, spliced genomic spans, and all EXON-only fragments without orientation-resolved strand correction. A new counter must be gated more narrowly: unique mapper, non-chimeric, non-artifact, unspliced, EXON-only mask, and fully contained in one EXON region by observed fragment span.

Implication: Add exon_contained_counts_by_orient as a subset counter. It should not be required to sum to per_region_counts[:, MASK_EXON]; the correct validation is shape/dtype plus row-sum less than or equal to that EXON-only row count.

Audit Entry 3: Region Partition Semantics

Files: src/rigel/calibration/regions.py, src/rigel/native/calibration/region_index.h, tests/test_region_partition.py.

The region table tiles references with INTERGENIC, INTRON, and EXON rows. EXON wins wherever any-strand exon coverage exists. Region strand is a bitwise flag: NONE, POS, NEG, or AMBIG. For EXON rows, the strand is derived from exon overlap only; for INTRON rows, it is derived from transcript-span overlap.

Boundary eligibility flags identify internal exon edges, not terminal TSS/TES sides. Single-exon transcripts therefore produce EXON rows with no boundary flux eligibility. This is exactly where EXON-contained strand deconvolution can add useful evidence in stranded libraries.

Implication: EXON-contained evidence can only be trusted on POS or NEG rows. AMBIG rows should remain boundary-only unless a later model learns separate strand mixture geometry.

Audit Entry 4: Global Density Computation

Files: src/rigel/calibration/density_global.py, tests/test_density_global.py.

The global density layer reduces the region table and payload into three densities: INTERGENIC, INTRON, and EXON-INTRON. INTERGENIC and INTRON use FL-weighted contained opportunity l_eff_contained(). EXON-INTRON uses boundary-crossing opportunity boundary_crossing_exposure() multiplied by eligible boundary sides.

Current EXON-region gDNA projection uses EXON-INTRON boundary density for all exonic contained opportunity. This is the current behavior the requested feature should augment rather than delete.

Implication: The global density schema needs a fourth raw channel, EXON-CONTAINED, plus a reconciled EXON composite density used for exonic projection. Boundary-specific diagnostics should remain visible.

Audit Entry 5: Regional Exposure Builder

Files: src/rigel/calibration/_regional_exposure.py, tests/test_regional_exposure.py.

The regional exposure builder constructs a single relative gDNA exposure field A_r. Today its EXON rows are driven by boundary evidence only: Y from strand-corrected boundary counters and E from boundary opportunity. The model then estimates a global rate, applies NB/Gamma-Poisson shrinkage, and converts per-region rho_hat into weights.

This is the most natural place to fuse per-region boundary and EXON-contained evidence, because it already works in count/opportunity space and already has strand-aware correction helpers. It also already converts NB alpha into a bp-equivalent opportunity length, avoiding the kappa-units bug documented on 2026-05-19.

Implication: For EXON rows, build composite evidence Y_ex = Y_boundary + w_ss * Y_contained and E_ex = E_boundary + w_ss * E_contained, where w_ss is zero when strand correction is unusable and otherwise scales with squared strand contrast.

Audit Entry 6: Locus Prior and EM Handoff

Files: src/rigel/calibration/locus_prior.py, src/rigel/pipeline.py, tests/test_per_locus_gdna_mass.py, tests/test_assemble_priors.py, tests/test_bayesian_prior_acceptance.py.

The diagnostic locoregional path estimates intergenic, intron, boundary-observed, and exon-only-imputed mass. The canonical EM prior remains global-only: expected_gdna_count_global() accepts no payload and must not use local counts. Tests explicitly pin that contract.

The production EM prior count is scaled into gdna_prior_count_em using regional exposure-adjusted gdna_eff_len. Per-unit numerator weighting is retained as a legacy helper but is not called in production v4.3.

Implication: Add local EXON-contained counts only to diagnostic locoregional estimates and regional exposure. The canonical prior should consume the global EXON composite density, preserving the no-local-payload contract.

Key Findings

FindingImpactRequired action
No EXON-contained orientation payload exists. The Python strand deconvolution code cannot be applied to fully contained EXON fragments yet. Add a native subset counter and thread it through CalibrationScanPayload and PayloadArrays.
EXON-only FL histogram must remain excluded from the gDNA FL pool. Adding EXON-only to FL training would reintroduce the spliced-genomic-span and mature-RNA contamination traps. Use the new counter for density inference only; leave extract_gdna_counts() unchanged.
Boundary flux remains necessary. Unstranded libraries and ambiguous-strand EXON rows cannot use contained strand deconvolution. Use boundary-only fallback whenever strand contrast is unidentifiable or contained rows are not strand-informative.
Evidence should be fused in count/opportunity space with precision safeguards. A naive average of densities ignores denominators, while raw opportunity alone can overtrust a giant but noisy EXON-contained channel. Scale contained evidence by strand reliability and kappa-capped precision opportunity, then combine Y and E before shrinkage where possible.
The canonical prior is global-only by design. Letting local EXON-contained counts directly change gdna_prior_count would break existing Bayesian-prior invariants. Use local counts for diagnostics and exposure learning; use global composite density for canonical exonic prior projection.

Design Decisions Recorded During Audit

  1. Add EXON-contained as an orientation-resolved subset counter, not as a new mask state.
  2. Gate EXON-contained evidence on splice_type == SPLICE_UNSPLICED, obs_mask == mask::EXON, EXON region type, and exact containment frag_start >= region_start and frag_end <= region_end.
  3. Do not add EXON-contained counts to the gDNA FL model in phase 1.
  4. Set contained strand reliability to zero unless strand_correction_usable() passes and the region strand is POS or NEG.
  5. Use signed_strand_contrast ** 2 as the first implementation of strand reliability, then combine it with kappa-capped precision opportunity rather than treating it as a complete inverse-variance weight.
  6. Preserve boundary-specific diagnostics and add EXON composite diagnostics rather than overwriting EXON-INTRON.

Open Questions For Implementation Review

  • Whether EXON-contained exact containment should eventually require additional boundary clearance. The v1 plan keeps exact containment because it matches l_eff_contained().
  • Whether the first strand reliability factor contrast ** 2 should later be replaced by a full delta-method variance estimate using same/opp/total counts. The v1 choice is simple, monotonic, and is now paired with kappa-capped precision opportunity.
  • Whether to write per_locus_gdna_df as an explicit output artifact. It currently lives inside CalibrationResult; the implementation can add diagnostics without changing CLI outputs, or add a new output in a later PR.

Audit Entry 7: External Critique Evaluation Addendum

Date: 2026-05-20. A second-pass critique was evaluated against the code paths audited above, and the markdown plan was revised accordingly.

Critique pointDispositionPlan update
AMBIG EXON rows may be exactly the dense loci motivating the feature. Adopted as a v1 limitation, not solved in v1. The plan now requires POS/NEG versus AMBIG opportunity diagnostics and calls out per-strand AMBIG sub-regions or payloads as follow-up work.
contrast ** 2 is not a full inverse-variance weight. Adopted with qualification. The plan now treats contrast ** 2 as strand reliability only and adds kappa-capped precision opportunity for evidence fusion.
Clip-before-sum row moments bias EXON-contained evidence upward. Adopted. The plan now avoids new EXON-contained clip-before-shrink behavior and floors final rates instead.
Opportunity-only fusion lets giant EXONs dominate sparse contained evidence. Adopted. Composite and regional fusion now use precision opportunity E * beta / (E + beta), with beta = alpha / rho.
Canonical prior projection would silently shift boundary terms. Adopted. The plan now keeps boundary-crossing expected counts on exon_intron.rho and applies exon_composite.rho only to EXON-contained projection.
Half-open containment edge needs explicit tests. Adopted. The plan now pins frag_end == region.end as contained and not a right-boundary crossing at q=1.
Use int32_t for memory. Not adopted for v1. The plan keeps int64_t for schema consistency and overflow safety, but records the memory cost and leaves int32_t as a separate migration if needed.
