## Golden review and the additional concern

All 21 golden scenarios were replayed, and both actual tables and existing expected tables
were saved outside `tests/golden/`. Every changed numeric column and scalar is retained.
The eight failures reproduce. The fresh current outputs pass the existing goldens.

The follow-up disposition audit also checks every table's schema, dtype, identity and
text field, and independently reconstructs all saved truth scores and pool totals.
It distinguishes small output movements from the combined stress concerns without
accepting either. The per-case table has one home under **GOLDEN DISPOSITION AUDIT**
in the ISSUES entry above. `golden_disposition.py` records input hashes and explicit
hold dispositions in `golden_disposition.json`; it performs no new pipeline run.

The extreme combined stress scenario exposes a count regression much larger than its
transcript-table change. Read-name truth and intergenic accounting establish that the DNA
pool moves away from truth. A separate oracle partition validates each structural class.

The mechanism controls vary factory presence on both the current and observational native
builds. With its strand channel inactive, this case gives bit-identical counts between the
two native builds: factory removal explains the difference. A further intervention preserves
each original fitted landscape while removing the factory. It repairs much of the pool
shift but leaves local class errors. This is evidence for retaining both the local-information
and population-feedback questions in the general design; it is not a proposal to freeze an
old population, reinstate the intron assumption or tune to this fixture.

The moderate combined stress case is retained alongside it. Its strand channel is active,
so the observational native change can also affect it. All observed and true object counts
are saved for subsequent comparisons, with regions and boundaries separate.

The subsequent [weak-strand evidence trace](RNA_WEAK_STRAND_EVIDENCE_CHECKPOINT.md)
rules out admission as the explanation in these two fixtures and localizes excessive
certainty in the point-count interface. The error also predates the population refits;
the completed frozen estimator/input comparison improves introns but trades errors
between other classes. It is not a sufficient replacement population model. Reliability
weights remained unchanged in that contrast. The subsequent equal-weight experiment
was separately approved and completed; it also trades class errors and exposes population
readout sensitivity, as recorded in the admission checkpoint.

## Observation-only message interface

The owner has paused statistical research to consolidate the production foundation.
The same count-only worktree now removes message inputs that became unused when its
strand claims switched to the exact conditional-binomial observation law:

- `TransferPolicy` and `Policy` carry `kappa: float | None`, rather than a three-value
  strand-model tuple. `SilentPolicy` supplies no strand claim. `_Strand.model` is deleted.
- `sweep.py` and `solve_blocks` no longer carry the two policy dispersion arguments.
  The count solver's own beliefs and dispersions remain, with their existing consumers.
- The native message `Chain` has no belief or dispersion fields. Its diagnostic
  `transfer_prepare` binding has no corresponding arguments either.
- The shared test context drops its belief field; every caller uses the smaller
  interface. Source comments now describe the observed likelihood rather than the
  retired belief-frozen width.

There is no statistical or arithmetic change. The original numerical law and wiring
checks remain; the former incoming-belief invariance check was replaced by an
interface contract that rejects the three removed inputs. That contract alone did not
prove full-sweep invariance; the final landing above closes this review finding.
Those specifications were
run against the old implementation first, and actual native copies deliberately
restore each argument after the cleanup. Separate compiled defects challenge the
likelihood, strand orientation and source-availability rules.

All outcomes have their authoritative home under **OBSERVATION-ONLY INTERFACE CLEANUP**
in the ISSUES entry above. The full-suite failure set is unchanged from the reviewed
count candidate, and no golden change is accepted by this refactor. The end-to-end
identity check uses the maintained `rename_identity.py` with fractional assignment;
all published calibration fields are also compared by name on the existing cached
conditions, not merely as an unordered collection.
